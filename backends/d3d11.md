The Windows backend uses **Direct3D 11** for GPU rendering and **shared handles** (`HANDLE`) for cross-process texture sharing.

## Overview

Ring textures use `D3D11_RESOURCE_MISC_SHARED_NTHANDLE` together with
`D3D11_RESOURCE_MISC_SHARED_KEYEDMUTEX`. The receiver duplicates the sender's NT
handle and opens it with `ID3D11Device1::OpenSharedResource1`. A keyed mutex
protects access to the shared pixels.

## How It Works

```
Sender Process                              Receiver Process
─────────────────                          ─────────────────
D3D11 Device                               D3D11 Device
    │                                           │
    ├── Create shared texture                    │
    │   (NT handle + keyed mutex)              │
    ├── Get shared HANDLE                       │
    ├── Acquire key 0, invalidate old slot      │
    ├── Render into texture                     │
    │      Publish HANDLE                       │
    │      via shared state                     │
    ├── Release key 0                           │
    │                                           ├── OpenSharedResource1
    │                                           ├── Acquire key 0
    │                                           ├── Revalidate slot metadata
    │                                           ├── Read texture
    │                                           │
    └── Ring buffer (N textures)                └── Release key 0
```

## Thread Safety

Writer and receiver acquisitions/releases all use **key 0**. A writable frame
owns its lease before the application gets the texture and retains it through
GPU writes or CPU upload, slot metadata publication, and commit. CPU mapping
unlock completes the upload; it does not release a live writable owner's lease.
Independent CPU mappings keep that lease and the texture alive after the
writable frame or sender is destroyed.

Writer acquisition probes ring slots with zero wait, skips held slots, and
returns `Timeout` when all are busy. Receiver `timeout_ms=0` is nonblocking;
positive timeouts use the remaining acquisition budget. Only `S_OK` means
ownership was acquired. An abandoned mutex invalidates its resource; the sender
retires/recreates it instead of writing through it.

Multiple receivers can acquire the same publication sequentially. This is
latest-frame sharing, not a queue guaranteeing delivery of every frame. Before
reusing storage, the writer invalidates the old slot publication. Discarding a
rewrite does not make old metadata valid again. Receivers recheck metadata after
acquiring ownership to detect reuse races.

`publish_external_texture` is unsupported on D3D11: publication cannot
retroactively protect writes to a borrowed texture. Use writable-frame
publication or `publish_native_texture` (copy into a sender-owned leased slot).
This protocol uses sender-state version **7 on every backend**; version 6 peers
are rejected. The directory stays at version 6 with unchanged layout. Both
applications must update their core. See [nozzle-dev#187](https://github.com/nozzle-io/nozzle-dev/issues/187)
for exact-SHA CI evidence and the separate physical-Windows verification status.

## Zero-Copy

Texture data is shared via GPU memory. Both processes reference the same D3D11 texture through the shared handle. Transfer mode is `zero_copy_shared_texture`.

## Backend API

```cpp
#include <nozzle/backends/d3d11.hpp>

namespace nozzle::d3d11 {

Result<device> wrap_device(const DeviceDesc &desc);
Result<texture> wrap_texture(const TextureWrapDesc &desc);
ID3D11Texture2D *get_texture(const texture &tex);
HANDLE get_shared_handle(const texture &tex);

}
```

### Types

```cpp
struct ID3D11Device;
struct ID3D11DeviceContext;
struct ID3D11Texture2D;
```

### DeviceDesc

```cpp
struct DeviceDesc {
    ID3D11Device *device{nullptr};
    ID3D11DeviceContext *context{nullptr};
};
```

### TextureWrapDesc

```cpp
struct TextureWrapDesc {
    ID3D11Texture2D *texture{nullptr};
    uint32_t dxgi_format{0}; // DXGI_FORMAT as uint32_t
    uint32_t width{0};
    uint32_t height{0};
};
```

### wrap_device

Wrap an existing D3D11 device and context.

```cpp
Result<device> wrap_device(const DeviceDesc &desc);
```

```cpp
auto dev = nozzle::d3d11::wrap_device({
    .device = d3d_device,
    .context = d3d_context
}).value();
```

### wrap_texture

Wrap an existing shared D3D11 texture.

```cpp
Result<texture> wrap_texture(const TextureWrapDesc &desc);
```

### get_texture / get_shared_handle

Extract native handles from a nozzle texture.

```cpp
ID3D11Texture2D *get_texture(const texture &tex);
HANDLE get_shared_handle(const texture &tex);
```

## OpenGL Interop

Windows GL publication attempts `WGL_NV_DX_interop2` when the current context,
driver, and texture support it, otherwise falling back to CPU readback/staging.
Both routes write under the sender's writable-frame lease and publish only at
commit. WGL object locking is separate from that D3D11 lease. The receive-to-GL
copy path uses CPU staging/upload.

```cpp
#include <nozzle/backends/opengl.hpp>

nozzle::gl::gl_texture_desc gl_desc{
    .name = gl_texture_name,
    .target = GL_TEXTURE_2D,
    .width = 1920,
    .height = 1080,
    .format = nozzle::texture_format::bgra8_unorm
};

// Publish via WGL GPU interop when supported, otherwise CPU staging.
nozzle::gl::publish_gl_texture(sender, gl_desc);

// Copy received frame → D3D11 → glTexSubImage2D
auto frame = receiver.acquire_frame({.timeout_ms = 1000}).value();
nozzle::gl::copy_frame_to_gl_texture(frame, gl_desc);
```

## Format Mapping

| Nozzle Format | DXGI_FORMAT |
|---------------|-------------|
| `r8_unorm` | `DXGI_FORMAT_R8_UNORM` |
| `rg8_unorm` | `DXGI_FORMAT_R8G8_UNORM` |
| `rgba8_unorm` | `DXGI_FORMAT_R8G8B8A8_UNORM` |
| `bgra8_unorm` | `DXGI_FORMAT_B8G8R8A8_UNORM` |
| `rgba8_srgb` | `DXGI_FORMAT_R8G8B8A8_UNORM_SRGB` |
| `r16_float` | `DXGI_FORMAT_R16_FLOAT` |
| `rgba16_float` | `DXGI_FORMAT_R16G16B16A16_FLOAT` |
| `r32_float` | `DXGI_FORMAT_R32_FLOAT` |
| `rgba32_float` | `DXGI_FORMAT_R32G32B32A32_FLOAT` |
| `depth32_float` | `DXGI_FORMAT_D32_FLOAT` |

## Requirements

- Windows 10+
- D3D11 runtime (included in Windows)
- `d3d11.lib`, `dxgi.lib`
